## きっかけ

返答の中のコミット ID（`決着させた ( 6e985ac ) ので`）を、16 進の文字のまま読み上げていた。

背景（決めたこと）:

- 形をかなり限定して、明らかにコミット ID と分かるものだけを消す
  - 16 進は小文字の 7 桁。数字だけ・英字だけでもよい
  - カッコは半角の `(` `)` だけ。カッコの内側と外側の両方にスペースがあるものだけ
- 消した後、前後のスペースも消す（`foo ( 6e985ac ) bar` は `foobar` になる）
- `` ` `` を消した後に消すので、`` ( `6e985ac` ) `` も対象になる

## やったこと

- `src/ccspk/hook.py` の `to_speech` で、`` ` `` などを消した直後に
  `[ \t]+\([ \t]+[0-9a-f]{7}[ \t]+\)[ \t]+` を空文字に置き換える。改行はスペースに数えない
- `demo()` に例を足した（消える形、スペースが欠ける 4 通り、大文字・6 桁・8 桁・全角カッコ、改行）。
  reviewer・verifier の指摘で、改行の例と `(` の直後にスペースが無い例を足した
- `docs/UsersGuide.md` の「記号と数字」に書き足した

## 確かめたこと

- `uv run ccspk test` が通る
- verifier が正規表現に 10 通りの変異を入れ、9 通りで `ccspk test` が落ちた。落ちなかった
  「`(` の直後の `[ \t]+` → `*`」は、例を足した後に main が同じ変異で落ちることを確かめた。
  reviewer が挙げた「`[ \t]` → `\s`」も、例を足した後に落ちることを確かめた
- UsersGuide.md の 2 つの例が `to_speech` の結果と一致した（[verifier-report.md](../agents/TODO-032/verifier-report.md)）

## 残ること

仕様どおりだが、次の形では消えない、または読みが崩れる（reviewer の報告。実害は未確認）。

- `)` が行末・返答の末尾にあるとき、`)。` のときは消えずに読まれる
- ID が 2 つ続くと、`a ( 1234567 ) ( 7654321 ) b` が `a( 7654321 ) b` になり、2 つ目が残る
- 英語に挟まれると `fix ( 6e985ac ) and` が `fixand` になる
