## 形態素解析の候補

`measure.py` で、このプロジェクトの会話ログの返答 200 件（`to_speech()` 後、15,146 字）を切り出した。
Python 3.13、一時の venv。

| 候補 | 大きさ（site-packages） | 読み込み | 200 件の切り出し | 漢字を含む単語（異なり） |
|------|------|------|------|------|
| 正規表現だけ | 0 | 0 | 0.00 秒 | 374 |
| janome（純 Python） | 113 MB | 1.99 秒 | 0.20 秒 | 508 |
| fugashi + unidic-lite | 1.2 + 249 MB | 0.01 秒 | 0.01 秒 | 505 |
| sudachipy + sudachidict_core（C 単位） | 4.9 + 193 MB | 0.03 秒 | 0.01 秒 | 508 |

- 英字は正規表現のほうが素直に切れる。3 つの解析器は `README.md` を `README`・`md` に、
  コミット ID（`a1a9b44`）を 1 字ずつに割る
- 正規表現だけだと、漢字の連なりで切るので送り仮名が落ちる（`上書`・`一度見`・`今回決`）。
  その形を `/audio_query` に渡すと、単語として読ませたことにならない
- 解析器 3 つは漢字の切り方がほぼ同じ。sudachipy の C 単位は複合語を 1 つにまとめる
  （`優先度`・`作業中`・`リンク先`）。辞書に登録する単位に近い
- 解析器は動詞の活用形も返す（`試さ`・`続い`・`空い`）。単語だけで読ませると誤判定の元になる

## claude -p の料金と時間

`words.py` で、英字は正規表現、漢字は sudachipy（C）で切り出し、エンジンの読みを付けた（683 語、1.4 秒）。
プロンプトは `prompt.txt`。空のディレクトリで次を実行した。

```sh
claude -p --model sonnet --setting-sources "" --tools "" --no-session-persistence --output-format json "$(cat prompt.txt)" < in.tsv
```

| 語数 | 料金 | 時間 | cache_creation | output |

| 30（返答 1 回分ほど） | $0.018 | 7.1 秒 | 2,703 | 659 |

- 30 語では 4 語を誤りとした（`TODO`・`fugashi+unidic-lite`・`sudachipy`・`to`）。`TODO` は辞書に登録済み。
  `to` は単語だけで読ませたときの読みで、文の中では問題にならないことがある
- 683 語では、英単語の読み（`reviewer` → レビュアー など）、活用形（`試さ` → タメサ）、
  1 字の漢字（`行` → ギョウ、`重` → ジュウ）を挙げた。1 字の漢字と活用形は文脈で読みが変わるので、
  登録すると他の文の読みを壊す

## 点検の claude -p がフックを走らせないようにする方法

- `--bare` はフックを飛ばすが、認証が `ANTHROPIC_API_KEY` か apiKeyHelper だけになり、OAuth を読まない
- `--setting-sources ""` は利用者・プロジェクトの設定を読まないので、フックも `env`（`CCSPK_SPEAK=1`）も入らない。
  OAuth のまま動いた。実行後、`$XDG_RUNTIME_DIR/ccspk.last`（最後に読んだ文）は点検の返答に変わっていなかった。
  cache_creation が 2,703 なので、`~/.claude/CLAUDE.md` も読んでいない
