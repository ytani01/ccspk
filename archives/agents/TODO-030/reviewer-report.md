### 1. docs/UsersGuide.md:153-155 「数字の前後のスペースは残す」が、2 つ上の項目と食い違う

- 何が: 同じ節の 148 行目に「数字の直後のスペースは、同じ行で日本語の文字が続くときだけ消す

## 検討

### 2. hook.py:231-233 行をまたいだ「日本語の行末＋英単語の行頭」も詰めて、行の間の間が消える

- 何が: `to_speech` が改行をスペースにした後で詰めるので、行の境目も詰める。数字では
  「行をまたぐときはつなげない」（hook.py:338、`手順 1\n次へ`）としているのに、英単語ではつなげる
- 実測:
  - `chunks(to_speech("設定は\nreviewer に。"))` → `['設定はreviewer', 'に。']`
  - 箇条書き 2 行を想定した `設定した README を直した`（詰める前）→ `セッテエ'/_シタ'、リ'イドミイ、オ'/ナオシ'タ`
  - 同じ文を詰めた後の `設定したREADMEを直した` → `セッテエ'/_シタ'/リ'イドミイオ/ナオシ'タ`
- 実害: 行の間の「、」の間が消える。数字の「1次」のような読み違いは出ていない
  （アクセント句の区切り `/` は残る）。日本語同士の行の境目（`設定した\n次へ`）は空白が残って
  間が入るので、行頭が英単語かどうかで扱いが分かれる。問題にするかは判断が要る（報告だけ）

### 3. hook.py:224 split_first がスペースで切った所が英単語と日本語の境目だと、そこの間は残る

- 何が: 1・2 文目で、`CUT` が 30 字以内に無く、8 字目以降にスペースがあると、最初のスペースで
  2 つに切る。日本語の返答では、そのスペースは英単語と助詞の境目であることが多い
- 実測: `chunks(to_speech("**reviewer** の指摘。"))` → `['reviewer', 'の指摘。']`、
  `chunks("settings.json の登録は通りました。")` → `['settings.json', 'の登録は通りました。']`
  （demo の 385 行目がこの形を期待値にしている）。別々に合成するので、詰める前と同じく間が入る
- 「切った後に詰める」という決めたことどおりで、変更による後退ではない。この項目の目的
  （`reviewer の` の間を消す）が、短い 1・2 文目では果たせないことがある、という報告だけ
