## 問題なしの観点

- 文の分け方: `.` は区切りに入れていないので `1.5`・`...`・`e.g.` では切れない。全角「！？」と
  半角「!?」の両方で切れ、後ろの空白は次の文に付かない。句点の無い文は 1 つのまま。
  `!=` や `?.` のようなコード片の途中でも切れるが、短い間が入るだけ。英語の文は `.` で
  切れないので 1 つにまとまる（日本語の返答が主なので実害は小さい）。
- 目印の判定の誤り: 本文は argv の 1 要素なので、本文に `--play` を含んでも要素として `--play`
  とは一致しない。本文がちょうど `--play` のときも、`sys.argv[1:2]` で判定し `sys.argv[2]` を
  本文として取るので正しく動く。
- 本文を argv で渡すこと: 180 文字（UTF-8 で最大 540 バイト程度）は 1 要素の上限 128 KiB に
  遠く及ばない。`-` で始まる本文も、スクリプトのパスより後ろの引数は Python が解釈せず、
  argparse も使っていないので問題ない。`ps` に本文が見えるのは、直す前も curl の URL に
  入っていたので変わらない。NUL を含む本文で Popen が ValueError になるのも直す前と同じ。
- `sys.executable` と `__file__`: settings.json は `python3 "$HOME/.claude/hooks/speak-response.py"`
  で呼ぶので、`__file__` は絶対パス、`sys.executable` は hook を動かした python3 と同じになる。
  子は標準ライブラリだけを使う。
